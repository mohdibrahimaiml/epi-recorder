What EPI is

What is EPI, in one sentence?

EPI turns each decision an AI system makes into one sealed file (a .epi file): what the AI was given, what it decided and why, which model and version answered, and who approved it. Anyone can check that file themselves, offline, without trusting whoever made it.

Who is it for?

Two people. AI vendors whose systems make or recommend decisions for regulated customers, such as insurers, lenders and banks. And the reviewers on the customer side (compliance, risk, audit) who have to explain or defend those decisions.

How is this different from logs and observability tools?

Logs and tracing tools (LangSmith, Arize, Datadog and similar) are built for your engineers and live inside your systems, so your customer has to trust you. A .epi file leaves your platform: your customer keeps it and checks it without you.

How is it different from AI governance platforms?

Governance platforms (Credo AI, Monitaur and similar) document your policies, model inventory and risk assessments. EPI produces the record of each individual decision. They work well together: the platform says what should happen, the record shows what did.

Signing a log sounds easy. Why can't we build this ourselves?

Signing is the easy part. What matters is who holds the record and who can check it: the customer keeps the file, checks it offline with an open-source verifier, a reviewer can read it in a browser, and an independent witness exposes a record that was later edited, re-signed or deleted. You can build all of that; EPI is that work already done and open source.

What a check proves, and what it does not

What does a passing check prove?

That the file has not changed since it was sealed, and that its signature matches the key it carries. With a timestamp from a public timestamp service, it also proves the file existed no later than that time.

What does it not prove?

It does not prove the AI's decision was right, that every action of the system was recorded, or who signed it until you pin the signer's key yourself. A .epi file is evidence you can inspect, not a certificate. See the trust model.

What if the vendor edits a record and signs it again?

On its own, a re-signed file would check out. That is what the witness is for: when a record is sealed, its fingerprint is sent to a log the vendor does not control. A re-signed file no longer matches that fingerprint, and a record that disappears shows up as a gap in the numbering. EPI Cloud runs a hosted witness on paid plans, and the customer can run their own witness for free with epi witness serve.

How does the customer know who signed the file?

The key inside a file is only the file's own claim. The customer pins the sender's key once, through a separate channel (for example a fingerprint read out on a call), with epi keys trust. With --policy strict, a check fails until the signer is pinned.

Can we see the record fail?

Yes. Open the verifier, drop in the sample file and use the tamper lab to change one byte: the check fails. The proof page shows the same tests on the command line, including an edited decision inside a properly rebuilt file.

Data, privacy and security

Do you see our data or our customers' data?

Recording, sealing and checking happen on your own machines; your .epi files are not sent to us. The browser check at /verify runs in the browser tab and uploads nothing. A witness receives only a fingerprint (a hash), never the record. EPI Cloud stores only the files you choose to upload. See the privacy policy.

Are secrets and personal data removed?

Redaction is on by default. It removes API keys, tokens, email addresses, phone numbers, card numbers and US social security number patterns. It works by matching patterns, so review what your system records before relying on it.

Is anything sent over the internet when a record is sealed?

By default the tool asks a public timestamp service (freetsa.org, then DigiCert) to timestamp the record. Only a hash is sent, never the contents. Turn it off with EPI_NOTARIZE=0, or use your own timestamp service. Usage telemetry is off unless you turn it on.

Where is EPI Cloud hosted?

On Cloudflare. Card payments for Cloud subscriptions are handled by Paddle, our Merchant of Record.

Can we run everything ourselves?

Yes. The recorder, the witness receiver and the verifier run on your own infrastructure, and EPI Cloud is optional. The paid epi-enterprise package (Growth, Enterprise and the full engagement) adds the gateway, adapters, guardrails, private deployment and a licence issued to your organisation.

Do you sign NDAs and data processing agreements?

NDAs: yes, mutual, on your paper or ours. For any work that involves personal data we review your data processing agreement first, and if we cannot accept a term we say so before the engagement starts.

Is it open source?

Yes. The recorder, verifier and viewer are open source under Apache-2.0 on GitHub. Releases ship checksums, Sigstore signatures, a software bill of materials, and PyPI build attestations, so you can trace every package to the public build that made it.

Setup

Which AI stacks does it work with?

Free: OpenAI and Anthropic clients, LangChain, pytest, and AGT traces. In the paid epi-enterprise package: LiteLLM, LangGraph, OpenTelemetry, Guardrails and a self-hosted gateway. See integrations.

Can an AI assistant use it?

Yes. The MCP server exposes epi_seal_record, epi_verify and epi_export_summary. The MCP SDK is an optional extra and the package ships three executables, so name both: uvx --from "epi-recorder[mcp]" epi-mcp. Hosts that need a URL use epi-mcp-http (Streamable HTTP at /mcp).

How much code do we have to change?

For an OpenAI-based agent, a few lines: wrap the client and put the run inside with record("decision.epi"):. In the paid readiness assessment we do the integration for one of your workflows in five working days.

Will it slow our system down?

Recording happens in your own process and the file is sealed when the run ends. The overhead depends on your workload, so we measure it on one of your real workflows during the assessment rather than quote a number here.

Does the reviewer need to install anything?

No. They open epilabs.org/verify in a browser and drop the file in. Nothing is uploaded. Technical reviewers can also use the free command line (pip install epi-recorder) or the Windows installer (unsigned until SignPath approval, so SmartScreen will warn).

Regulation

Does EPI make us compliant with the EU AI Act?

No tool does that on its own. EPI gives you evidence: a sealed record of each decision, and (with epi-enterprise) a pack you can use as input to the technical documentation Annex IV asks for. Whether you comply is for your compliance team and regulators to decide. This is not legal advice. See standards.

Does it help with explaining credit or claim decisions?

It keeps a sealed record of the reasons your system gave for each decision, together with the inputs, model and approval, so you can show them later exactly as they were. Whether those reasons meet a specific rule is a judgement for your compliance team.
