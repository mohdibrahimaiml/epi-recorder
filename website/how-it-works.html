Architecture & Wire Specification · v4.11.2

Inside an Envelope v2 evidence file.

Every .epi artifact is one self-contained Envelope v2 container. Sealed data-only (the default) it is a plain ZIP that any tool can open and epi verify can check offline; sealed with --with-viewer the same bytes are also an HTML+ZIP polyglot that opens in any browser with zero dependencies. 

demo.epi (Envelope v2)
├── [0..127] 128B Envelope Header
├── Embedded HTML Viewer (SHA-256 covered)
└── ZIP Payload
    ├── mimetype (application/vnd.epi+zip)
    ├── manifest.json (Ed25519 + JCS)
    ├── steps.jsonl (prev_hash chain)
    ├── environment.json (redacted)
    ├── policy.json & policy_evaluation.json
    └── artifacts/notarization/ (RFC 3161)

Context Manager Capture

from openai import OpenAI

    )

03 · Deterministic Policy

Rulebook & Fault Analyzer

Create epi_policy.json via epi policy init. With EPI_ENFORCE=1 or --policy strict, policy loading fails closed and records policy_load_status directly in the signed manifest.

One signed file per AI decision. Anyone can check it offline, without an account.
