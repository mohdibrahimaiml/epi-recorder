Use cases

Where agent decisions need a file

EPI is not a domain certification product. It is a portable sealed record of what an agent did — useful wherever “show me the run six months later” matters. Framework names are illustrative of demand, not claims of automatic compliance.

Financial services

Credit, fraud, refund, and underwriting agents. Seal the decision trail for internal audit and model risk review.

Healthcare & clinical AI

Decision support and workflow agents. Signed execution snapshots for review — not a 510(k) certificate by itself.

Insurance

Claims and underwriting agents. Full step trails for later reconstruction of “what the system did.”

Government & public sector

Benefits, procurement, and casework agents. Offline-verifiable evidence for oversight bodies.

AI safety & eval

Red-team and evaluation runs as sealed artifacts — reproducible evidence of what was tested.

Legal & document AI

Review and contract agents. Verifiable trails for “what did the model/agent do on this matter.”

Demo artifacts are illustrative. The eight sector demos (demo-*.epi in website/assets/demo/) were sealed with mocked LLM responses (deterministic fallback, GROQ_API_KEY not set) to keep the build reproducible without external API calls. The seal proves the file wasn't altered after sealing, not that a live model produced the text. For a live-model run, set GROQ_API_KEY and re-run python scripts/generate_sector_demo_epis.py.

How teams usually start

  1. Seal one real consequential agent path with the open-source CLI.
  2. Verify offline; pin org keys when identity matters.
  3. Optional: policy rules + fault analyzer for mechanical checks.
  4. Optional: hosted verify volume / remote SCITT for scale.
