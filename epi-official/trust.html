Verification Contract · Seal ≠ Identity ≠ Policy

Three questions. Never collapsed into one badge.

EPI separates cryptographic file integrity, signer identity pinning, and policy compliance in code so an auditor or underwriter sees the exact truth of what was proven.

# Strict Auditor / Insurer Command
$ epi verify FILE.epi \
--policy strict \
--witness-log witness.json \
--witness-pubkey <KEY> --offline
01 · Seal Integrity

SHA-256 + Ed25519 + JCS

Proves that no member file, step in steps.jsonl, or byte in the outer embedded HTML viewer was modified after sealing.

02 · Out-of-Band Key Pinning

Never Trust In-Band Keys

Listing a key in /.well-known/epi-trust-registry.json is informational only. Claim-ready verification requires pinning the sender’s key out of band (epi keys trust).

03 · Witness & TSA

Independent Time & Order

RFC 3161 timestamp tokens are verified offline against pinned TSA roots. EPI Cloud Witness logs hash-only Ed25519 receipts and daily signed checkpoints.
